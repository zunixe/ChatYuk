## 2. Temuan KEAMANAN

### SEC-01 · P0 · Realtime broadcast chat lewat channel publik — bisa disadap & dipalsukan
**Lokasi**
- Pengirim: `lib/services/chat_service_private.dart:311-326` (`_sendBroadcastOnce` payload berisi `text`, `type`, `sender_id`, `image_data`/`voice_path`, `poll`, `contact`), channel dibuat `:397-409` tanpa `RealtimeChannelConfig(private: true)`.
- Penerima: `lib/services/chat_stream_session.dart:857-891` — `onBroadcast('new_message')` **langsung memasukkan payload ke `_current` dan meng-emit ke UI** hanya dengan cek `chat_id == filterVal`.
- Topik deterministik: `chat_stream_session.dart:54` (`msg-private_<chatId>`), `chatId` 1:1 = `uid1_uid2` (`chat_service_private.dart:375-383`).
- Pola sama: typing `lib/services/chat_service_typing.dart:58,111`; `view_once_seen` `lib/services/chat_service_room.dart:228-242`; presence hub `lib/services/realtime_hub.dart:41,122` (`self: true`, tanpa `private`).
- Tidak ada migrasi yang membuat policy `realtime.messages` (grep `realtime.messages` di `supabase/migrations` = 0).

**Bukti/alasan.** Supabase Realtime: channel **tanpa** `private: true` dapat di-join siapa pun yang punya URL project + publishable key (ada di APK) dan nama topik. `postgres_changes` memang tunduk RLS, tapi **broadcast tidak** kecuali channel privat + policy di `realtime.messages`. UID user tersebar (profil publik, online users, room messages), jadi topik mudah dibentuk.

**Dampak.** (a) **Kerahasiaan**: penyadap menerima teks pesan privat realtime (foto/voice hanya path storage — tetap dilindungi RLS storage). (b) **Integritas**: penyerang `sendBroadcastMessage` ke topik korban → bubble palsu "dari lawan bicara" muncul di layar korban, masuk cache lokal (`scheduleCacheSave`) → **phishing/penipuan atas nama orang lain**. Ini persis skenario yang ditakuti aturan AGENTS.md ("disangka scam/akun dibajak").

**Rekomendasi (pilih A, atau B sebagai mitigasi cepat).**
- **A (benar):** aktifkan **private channels**: semua `_sb.channel(topic, opts: RealtimeChannelConfig(private: true))` + migrasi policy `realtime.messages` (SELECT/INSERT) yang memeriksa `realtime.topic()` → peserta `private_chats`/anggota room via `auth.uid()`. Nyalakan "Private channels only" di dashboard Realtime `[CEK DB LIVE]`. Perlu `setAuth` otomatis (supabase_flutter sudah meneruskan JWT).
- **B (cepat, ≤1 hari):** di penerima **jangan percaya payload**: perlakukan `new_message` broadcast hanya sebagai **sinyal** → panggil `reload()`/fetch by id lewat RLS, bukan insert payload. Hapus `text`/`image_data` dari payload pengirim (kirim `id` saja). Ini menutup pemalsuan & kebocoran isi; latensi tetap rendah (fetch 1 baris).
- Tambah test regresi: broadcast dengan `sender_id` bukan peserta → tidak muncul.

### SEC-02 · P0 · `refund_chat_point` bisa di-replay → koin tak terbatas
**Lokasi** `supabase/migrations/20260819000000_refund_chat_point.sql:12-48` (versi terbaru; tidak ada migrasi lain yang mendefinisikan ulang). Grant ke `authenticated` `:48`. Pemanggil client: `lib/mixins/chat_send_mixin.dart:385,388`, `chat_outbox_mixin.dart:288`, `chat_photo_send_mixin.dart:632,706,709,893,955,958`, `chat_file_send_mixin.dart:140`.

**Bukti.** Fungsi mengambil `spend_chat` **terakhir** untuk `msg_type` lalu insert `spend_refund` sebesar `-amount`. Tidak ada: (1) penanda bahwa baris spend itu sudah pernah di-refund, (2) cek `points_enabled`, (3) kaitan dengan pesan yang benar-benar gagal. Setiap panggilan ulang me-refund baris yang sama lagi. `deduct_chat_point` (`20260815120000_photo_paywall_point_settings.sql:256-283`) berjalan saat `points_enabled=true` & cost>0.

**Dampak.** User dengan 1 kali spend bisa memanggil RPC via REST (`/rest/v1/rpc/refund_chat_point`) N kali → saldo YukCoin naik tanpa batas → buka foto berbayar/fitur premium gratis; mengurangi nilai top-up Play Billing. Berlaku saat poin aktif (`app_settings.points_enabled`) `[CEK DB LIVE: nilai flag saat ini]`.

**Rekomendasi.**
1. Migrasi: `refund_chat_point` cek `not exists (select 1 from coin_ledger where type='spend_refund' and metadata->>'refund_of' = <id spend>)`, simpan `refund_of` = id baris spend; batasi jendela (mis. spend ≤ 10 menit); hormati `points_enabled`. Tambah `-- menyentuh:` bila fn ada di `scripts/frozen_functions.txt` (cek).
2. Lebih kuat (P1, terjadwal): pindahkan debit ke **server** — trigger `after insert on private_messages` yang memotong poin atomik; client tidak lagi memanggil `deduct/refund`. Menghapus seluruh kelas race "potong dobel / hilang tanpa refund" yang berulang di git log (`345415db`, `250534fa`).
3. pgTAP: `supabase/tests/points_test.sql` tambah kasus "refund dua kali → saldo hanya naik sekali".

### SEC-03 · P2 · Edge `link-preview`: SSRF dasar (tanpa blokir IP privat / batas redirect)
**Lokasi** `supabase/functions/link-preview/index.ts:37-42`; `supabase/functions/_shared/link_preview.ts:77-85` (`redirect: 'follow'`, validasi hanya `^https?://` + panjang). Dipakai juga `send-push`.
**Dampak.** User login bisa menyuruh server fetch URL arbitrer (termasuk `http://169.254.169.254`, host internal, atau redirect ke IP privat) dan membaca `og:*`/`<title>` hasilnya. Di Deno Deploy dampaknya terbatas, tapi tetap permukaan serangan + bisa dipakai sebagai proxy pemindai. Tidak ada rate-limit per user.
**Rekomendasi.** Resolve DNS → tolak IP privat/loopback/link-local/metadata; batasi redirect (maks 3, validasi ulang tiap hop); batasi ukuran body (mis. 512 KB) & content-type `text/html`; rate-limit per uid (tabel kecil atau KV).

### SEC-04 · P2 · Log tidak ter-strip di release (bocor uid/uid lawan ke logcat)
**Lokasi** ~45 `debugPrint(...)` tanpa guard `kDebugMode`/`dlog` (mis. `lib/services/device_info_service.dart:242` memakai `print` + `uid`, `lib/screens/admin_dummy_tab.dart:364-366` `print`, `lib/screens/private_chat/private_chat_*.dart`, `lib/providers/riverpod/call_provider.dart:50,61,81` mencetak stack navigasi). `lib/utils.dart:4-11` sudah menyediakan `dlog` yang di-tree-shake.
**Dampak.** Build release tetap menyusun string & menulis logcat (bisa dibaca app lain pada perangkat lama/rooted; juga biaya CPU kecil). Bertentangan dengan komentar `utils.dart:4-6`.
**Rekomendasi.** Ganti semua `debugPrint`/`print` di `lib/` → `dlog`. Tambah guard CI: `grep -rnE '^\s*(print|debugPrint)\(' lib --include='*.dart' | grep -v 'lib/utils.dart'` → 0.

### SEC-05 · P3 · URL fungsi TURN hardcode prod, melewati `AppEnv`
**Lokasi** `lib/config/call_config.dart:10-11`. Build `APP_ENV=dev` tetap memanggil edge function prod `turn-credentials` dengan JWT dev (gagal 401 → fallback openrelay). Rekomendasi: `'${AppEnv.supabaseUrl}/functions/v1/turn-credentials'`.

### SEC-06 · P3 · Kebersihan secret lokal
`.env` (tidak ter-track ✅) masih memuat `MIDTRANS_DASHBOARD_USERNAME/PASSWORD`, `CF_ACCOUNT_ID`, `CF_ANALYTICS_TOKEN` yang tidak ada di `.env.example`; fitur Midtrans sudah dihapus total. Rekomendasi: hapus key mati dari `.env`, sinkronkan `.env.example` (nama key saja), rotasi token Cloudflare bila masih dipakai `admin-cf-usage`.

### Yang SUDAH BAIK (jangan dibalik)
- Sesi Supabase di `FlutterSecureStorage` + migrasi legacy (`lib/config/supabase_config.dart:22-122`).
- Hanya publishable key di APK; secret via `--dart-define` (`lib/config/env.dart`); guard dev-tidak-boleh-sentuh-prod.
- Edge: `ai-reply` memvalidasi JWT = `sender_id` + cek keanggotaan chat (`index.ts:981-1025`); `fanout` service-role only; `telegram-webhook` cek secret header; `dummy-manage` cek email admin.
- Hardening 2026-09-28 (SECURITY_AUDIT.md): revoke EXECUTE anon/authenticated untuk fungsi internal, `search_path` di-set, view `profiles_public` dihapus, HIBP aktif.
- Policy private_messages: peserta + admin read-only (`20260928040000`, `20260929010000`), blokir ditegakkan server (`20261023100000`).
- Android: `allowBackup=false`, minify+shrink+obfuscate, flavor-gate admin + `check_release_apk.sh`.

### BUG-03 · P2 · Broadcast `new_message` tanpa `id` → potensi bubble dobel `[VERIFIKASI]`
**Lokasi** Payload pengirim `chat_service_private.dart:312-325` **tidak menyertakan `id`** (insert id tersedia di `:304`). Penerima `chat_stream_session.dart:864` fallback `id = 'bc-<micros>'`; dedupe hanya `by id` (`:865`, `:747`). Event `postgres_changes INSERT` untuk baris yang sama datang dengan id asli → lolos dedupe.
**Dampak.** Pesan sama tampil dua kali sampai reload/trim; cache lokal menyimpan id palsu `bc-…` (tidak pernah cocok dengan server → bisa muncul lagi saat replay). Perlu verifikasi dengan 2 device (mungkin ada dedupe lain di UI yang tidak saya temukan).
**Rekomendasi.** Sertakan `id` di payload broadcast (dan `created_at`), dedupe sekunder by `(sender_id, created_at, text)` untuk pesan tanpa id. Selaras dengan SEC-01 opsi B (broadcast = sinyal id saja) → masalah ini hilang otomatis. Test: `test/regression/r_stream_replay_test.dart` tambah kasus broadcast-lalu-insert.
